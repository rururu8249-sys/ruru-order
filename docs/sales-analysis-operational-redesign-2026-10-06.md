# 판매분석 운영 화면 재설계

## 확인된 구조와 문제

- `adminLiveMenu`: 판매분석의 기본 위치는 주문·입금. 기존 reports 링크도 같은 화면으로 연결한다.
- `SalesAnalysisPanel`: 조회 조건과 방송 선택, 전체 기간의 결제 합계 담당.
- `salesAnalysisLoader`: 주문 전체 페이지와 필요한 상품 메타데이터를 읽기 전용으로 한 번 조회한다. 일부 조회 실패 시 부분 합계를 표시하지 않는다.
- `liveOrderAdapter`: 주문서 단위 결제 상태·결제금액과 상품 줄 단위 금액을 분리한다. 이 금액 계산은 이번 화면 작업에서 변경하지 않는다.
- 이전 통합은 리포트의 `height:100%`와 내부 스크롤을 그대로 삽입한 후 상품 목록을 이어 붙였다. 구매자 목록이 상품 분석보다 먼저 길게 나오고 빈 공간도 발생했다. 하나의 운영 흐름이 아니라 두 화면을 쌓은 구성이었다.

## 운영 질문을 기준으로 한 정보 배치

1. 기간·판매 경로를 선택하고 전체 결제금액·상품금액·주문건수·판매수량을 확인한다. 전체 조건 합계임을 명시한다.
2. 방송을 선택하면 해당 방송 이름과 합계가 별도로 나타난다. 전체 합계와 선택 방송 합계를 혼동하지 않는다.
3. 기본 상세 보기는 상품·옵션별이다. 상품 사진과 이름, 색상별 사이즈·수량, 판매수량, 단가, 상품금액을 같은 행에서 비교한다.
4. 상품명·색상·사이즈 검색과 금액순·수량순·상품명순 정렬로 재방송/상품 준비 시 빠르게 찾는다.
5. 구매자별은 별도 보기로 전환한다. 닉네임·이름, 주문건수·수량·결제금액을 먼저 보여 주고 구매 상품은 필요할 때 펼친다. 고객 연락처는 이 분석 화면에 노출하지 않는다.

## 데이터·화면 안전 조건

- 같은 등록상품 ID·세부상품명·단가의 주문 줄은 묶되 색상과 사이즈의 원본 필드를 유지한다. 같은 이름·가격이라도 등록상품이 다르면 분류와 사진을 서로 물려받지 않도록 구분한다. 슬래시로 옵션 문자열을 재분해하지 않는다.
- 동일 상품의 서로 다른 단가는 구분한다. 수정 상품금액은 줄 전체 금액이므로 수량을 다시 곱하지 않는다.
- 결제금액과 상품금액은 구분한다. 배송비·카드 부가금액 등이 존재해 합계가 다를 수 있다.
- 상품 사진은 정확한 세부 상품 매핑만 사용한다. 사진이 없으면 다른 상품/브랜드 사진으로 대체하지 않는다.
- 보기 전환과 방송 전환에서 주문을 재조회하지 않는다. 조회 실패 시 최신 합계인 것처럼 이전 합계를 유지하지 않는다.
- 화면의 본문은 하나의 흐름으로 구성하고 기존 리포트 전체 화면을 삽입하지 않는다.
- 작은 화면은 표 영역 안에서만 가로 스크롤한다. 열 이름과 상품 식별 정보를 생략하지 않는다.
- 재고·주문·입금·환불 데이터 쓰기는 없다.

## 참고와 적용 판단

- [NN/g 업무용 데이터 표](https://www.nngroup.com/articles/data-tables/): 검색·비교 작업을 우선하며 관련 열을 가까이 배치한다. 이번 화면은 장식용 그래프보다 상품과 옵션 수량 비교가 주 작업이므로 표를 우선한다.
- [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/): 부가 정보를 필요할 때 보여 준다. 긴 고객 목록을 기본 상품 분석 아래에 항상 붙이지 않는다.
- [Shopify Sales reports](https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports/report-types/default-reports/sales-report): 상품·옵션 판매와 결제/배송 관련 금액의 의미를 구분한다. 해당 서비스의 정의를 그대로 이식하지 않고 현재 어댑터의 금액 의미를 유지한다.
- [W3C Tables](https://design-system.w3.org/styles/tables.html): caption, 행/열 헤더를 명시하며 작은 화면에서 표 구조를 보존한다.

## 검수 기준

- 상품 묶음·색상·사이즈 정렬, 수정금액·다수 수량, 단가 구분, 보기 전환 추가 조회 없음.
- PC 첫 화면에서 선택 방송과 상품 분석을 확인할 수 있고 구매자 전체 목록이 먼저 나오지 않음.
- 작은 화면에서 문서 전체 가로 넘침 없이 표 영역만 스크롤됨.
- 조회 실패·새로고침·방송 변경 시 이전 화면 합계가 최신인 것처럼 남지 않음.

## 검증 결과

- 회귀검사 23개 묶음 통과, Next.js 빌드·타입 검사 통과.
- 독립 소스 검토에서 동일 이름·단가의 서로 다른 등록상품 간 분류 혼합을 발견해 등록상품 ID 경계와 회귀검사를 추가했다. 재검토 승인.
- 운영 커밋 `5737622`, Vercel `dpl_CK2jM9UQwanxTgty1jVqVkjAxDbu` READY 확인.
- 전체 결제금액 269,219,460원 / 상품금액 259,548,974원으로 이전 검증과 일치.
- 명품고퀄의류4: 결제금액 4,449,925원 / 상품금액 4,369,000원 / 19건·23개. BB-60 M 3개·L 1개·XXL 2개, BB-58 S 2개·L 1개·XL 1개·XXL 1개 확인.
- 명품고퀄의류3: 결제금액 6,487,145원 / 상품금액 6,406,000원 / 26건·32개 확인.
- 가방 분류 필터와 BB-58 검색, 구매자 보기와 펼치기, 분석 복사 성공 안내를 운영에서 확인했다.
- 390px 화면: 문서 너비 375px, 표 영역 281px/표 640px로 표 내부만 가로 스크롤됨. 임시 화면 크기 변경은 복원했다.
- 브라우저 오류 기록은 기존 YouTube 채팅 iframe의 SHEET_CONTROLLER_TOKEN 오류 2건. 판매분석 앱 출처 오류는 기록에서 발견하지 않았다. 서버 전체 무오류를 의미하지 않는다.
- 주문·입금·환불·재고 데이터 변경은 수행하지 않았다. 이번 완료 범위는 판매분석 운영 화면이며 과거 전체 작업 목록의 완료를 뜻하지 않는다.
