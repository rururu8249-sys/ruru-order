# 회원 화면 실제 사용 검수 보완

기준: 배포 PR #49, main `43297a024fc302bb2cee0330f27f4d77325f6ac1`.

## 사용자 요청과 확인한 원인

2026-11-20 사용자가 실제 운영 화면 6장을 보고 닫기 중복, 차단 위치, 주문 구분, 그대로 남은 필터·메뉴를 수정하도록 요청했다. 기존 설계 확인 후 순서대로 실행하며, 중간 질문 때문에 작업을 중단하지 말라는 지시를 유지한다.

- 이전 코드에도 우상단 X와 본문 아래 닫기가 중복이었다. PR #49가 이를 상단 텍스트 닫기와 고정 푸터로 바꾸며 중복을 더 드러냈다. DESIGN-ADMIN §11은 동일 기능 중복을 금지한다. 이번 사용자 요청에 따라 회원 상세는 우상단 X 한 개로 정리한다.
- 차단 버튼은 모든 탭의 고정 푸터에 있고, 차단 회원의 기본 정보에는 별도 해제 버튼이 있어 중복된다. 기존 차단 정보·사유 수정·해제 묶음(CLAUDE 9/26 기록)을 보존하고 기본 정보의 회원 관리 영역 한 곳에 둔다. 정상 회원의 차단도 이 영역에 둔다. 차단 요청 함수·확인 절차는 그대로다.
- 주문 그룹은 이미 존재하지만 주문번호는 펼친 내용의 맨 아래에만 있고, 주문 경계와 내부 상품선이 모두 같은 1px 선이다. 조회나 묶기 계산을 바꾸지 않고 주문번호·일시·상태·금액 헤더와 주문 사이 간격으로 구분한다.
- 상태 select와 상단 전체·정상·관리필요 요약은 같은 상태를 중복 조작한다. 단 상단 차단은 번호만 차단한 항목까지 포함하는 별도 관리 창이므로 상태 필터와 합치면 안 된다.
- native select의 OS 메뉴는 클래스만 바꿔 통일할 수 없다. 전역 focus-visible outline과 로컬 ring도 겹친다. 공용 선택 컴포넌트로 정렬 메뉴를 구성하고 키보드 표시를 한 겹으로 둔다.
- 모바일은 DESIGN-ADMIN §13의 필터 시트와 CLAUDE 10/22 실제 배포 기록의 가로 스크롤이 다르다. 이번 요청에서는 현행 디자인 기준의 필터 시트로 정리하고 이 차이를 기록한다.

## 구현 선택

클래스만 수정하는 방식은 OS 메뉴와 중복 조작 구조를 해결하지 못한다. 전체 고객 화면/공용 전역 스타일을 재작성하면 관련 없는 화면까지 영향을 준다. **회원 화면의 표시 컴포넌트와 공용 선택 컨트롤만 정리**하는 방식을 작업자가 선택한다. 새 라이브러리는 추가하지 않는다.

## 화면 계약

1. 회원 상세 720px/폰 전체화면, X 44×44 한 개. 읽기 상태의 고정 푸터 없음. 편집 중에만 저장 푸터. 기존 Esc·포커스 복귀·사진·배경 닫기 0.6초 보호 유지.
2. 차단 사유·해제는 기본 정보의 기존 묶음 한 곳. 정상 회원 차단은 기본 정보 회원 관리 영역. 주문/포인트/접속 조회 탭에 위험 버튼을 고정하지 않는다.
3. 주문 하나를 하나의 article로 묶고 기존 surface-2 헤더, 12px 안쪽 여백, 그룹 사이 16px. 번호 없는 과거 주문에는 가짜 번호를 만들지 않는다. 상품 줄 수·상품·배송비·포인트·주소·방송 정보 유지. 상품별 중첩 카드 없음.
4. 상태는 전체·정상·차단·관리필요·카카오 미연동 칩 한 벌. 차단 칩 숫자는 회원만; 별도 ‘차단 목록’ 숫자는 회원+번호 차단. 전화번호 차단 도구 유지.
5. PC 검색·정렬·주문 있는 고객만·초기화. 모바일 상태 칩+필터 버튼, 검색·정렬·구매자 토글·초기화는 하단 시트. 즉시 반영을 유지하며 시트 닫기로 선택을 되돌리지 않는다.
6. 정렬 8개와 기본값(latest/all/빈 검색/buyersOnly=false), oldLogin의 기록 없음 우선, amount의 paidAmount 기준, 페이지 크기 20, 필터 변경 page=1, reset 시 selectedPhones 유지.
7. 회원 정렬 8개와 주문 이력 정렬 3개를 같은 선택 컨트롤로 표시한다. 선택 컨트롤: 선택값/disabled/aria 상태 일치. Enter·Space·방향키·Home·End·문자 탐색·Esc·Tab·바깥 클릭 지원. 시트/드로어 안에서 Esc는 열린 선택 메뉴만 먼저 닫는다. 키보드 포커스 ink 2px 한 겹, 마우스 클릭에 이중 테두리 없음.

8. 차단 조회 GET이 실패하거나 `tableReady=false`이면 차단 수를 확정하지 않고 재조회를 제공한다. 정상/차단 필터와 차단 조작만 대기한다. 전체 회원·검색·주문은 계속 읽을 수 있다. 열어 둔 상세는 조회 완료 상태를 반영하고, 전화번호 폼은 fieldset으로 비활성화해 입력값을 보존한다.
9. 모바일 시트→차단 목록은 기존 모달 포커스 훅으로 중첩 처리한다. 자식 창을 닫으면 시트의 진입 버튼, 시트까지 닫으면 필터 버튼으로 돌아온다.

## 차단 판정의 과거 의도 확인

Git 커밋 `e9d5a551035e13a90ad483d2608c69a34d0d9535`(2026-06-01)은 회원 UI의 차단 판정에서 `Boolean(profile.is_blocked)`를 제거하고 `Boolean(directBlockReason)`를 사용하도록 명시적으로 바꿨다. 이번 수정은 이 계산을 그대로 둔다. 프로필 플래그만으로 새 차단 기준을 만들지 않으며, API가 함께 저장하는 회원·번호 차단 fixture로 범위를 검증한다. 이 UI의 판정 근거를 서비스 전체의 단일 정책이라고 확대하지 않는다.

## 변경하지 않는 계약

카카오 로그인, canonical 계정, 전화번호 과거 주문 연결, 주문 그룹키, 조회 범위, 상태 분류, 금액/배송비/포인트 계산, 고객 저장·차단 API와 데이터는 변경하지 않는다. 전역 다른 관리자 화면의 스타일도 변경하지 않는다.
