# 임시 상품의 브랜드 이동 및 세부상품 정보 설계

상태: 설계 검토용. 기능 구현·운영 데이터 이동은 아직 수행하지 않음.

## 목적과 순서

판매기록 사진·옵션 개선을 먼저 완료한다. 다음으로 임시 독립 상품을 사용자가 선택한 브랜드 하위로 이동하고, 세부상품별 정보를 편집·확인할 수 있게 한다. 브랜드나 품번은 사진을 보고 자동 추정하지 않는다.

## 확인한 현재 구조

- 독립 상품은 `products` 행이며 주문은 `product_id`를 참조한다.
- 브랜드 세부상품은 별도 products 행이 아니라 `product_note` 안의 이름별 사진·가격·옵션·재고 자료다.
- 상품 편집의 한눈에 정보와 상세설명은 부모 상품에만 있으며 세부상품 편집에는 없다.
- 카탈로그 쓰기 API는 products/broadcasts/broadcast_products만 허용한다. 이동 때문에 이 API에 주문 쓰기 권한을 추가하지 않는다.

## 선택한 방향

단순 복사 후 원본 삭제는 사용하지 않는다. 원본 ID를 유지하는 연결형 이동을 사용한다. 관리자 목록은 브랜드 하위에 모아 보여주되 기존 주문의 ID·상품명·금액은 바꾸지 않는다. 기존 브랜드 세부상품 JSON 형식은 유지하고, 이동된 항목만 원본 상품 ID를 연결한다.

## 이동 화면

독립 상품의 더보기에 ‘브랜드 하위로 이동’을 둔다. 한 화면에서 대상 브랜드 검색·선택, 최종 상품명/품번 입력, 이동 전후 사진·가격·옵션·재고·설명 비교를 제공한다. 최종 확인 버튼은 ‘이 브랜드로 이동’으로 표시한다. 브랜드 선택은 필수다.

이름/품번 중복, 이미 이동된 상품, 브랜드 자체 이동, 가격 표현 불가능, 변경 중인 원본은 저장을 차단한다. 대표 브랜드 기본가보다 낮은 상품은 추가금 0으로 조용히 바꾸지 않고 정확한 판매가 표현을 지원한 뒤 이동한다.

## 연결·저장 원칙

이동 메타데이터에는 원본 ID, 대상 브랜드 ID, 세부상품 이름, 원래 이름, 이동 시각을 저장한다. 사진 URL·옵션별 재고·가격·설명은 원본 값 그대로 보존한다. 부모 편집이 연결된 항목을 덮어쓰지 않게 공통 상품 모델에서 해석한다.

이동은 관리자 인증된 서버 작업으로 수행하며 원본과 대상 변경을 한 트랜잭션에 묶는다. 조회 후 저장 사이 변경은 버전/수정 시각 검증으로 충돌 처리한다. 같은 요청 재시도는 이중 항목을 만들지 않는다. 실패하면 원본·대상이 모두 이전 상태를 유지한다.

기존 주문·방송 담기·물건챙기기·판매기록·위젯·고객 상품 선택에서 원본 ID의 연결을 해석한다. 브랜드와 원본을 같이 담아도 상품/재고를 이중 표시하거나 차감하지 않는다. 활성 주문이나 방송 참조가 있는 원본은 삭제하지 않는다. 이동 이력에서 원본으로 되돌리기를 제공한다.

## 세부상품 편집

‘기본정보’, ‘사진·옵션’, ‘한눈에 정보·상세설명’ 탭으로 나눈다. 상품 정보는 주문 안내와 별도다. 한눈에 정보는 부모와 같은 최대 6개/칩당 10자 규칙을 적용하고 입력 결과 미리보기를 둔다. 상세설명은 줄바꿈을 보존한다.

정보 적용 모드는 ‘브랜드 정보 따름 / 이 상품 정보 사용 / 표시 안 함’으로 명시한다. 비운 입력값만 보고 상속 여부를 추정하지 않는다. 고객이 해당 세부상품을 선택했을 때 사진·칩·설명이 그 상품 정보로 바뀌고 다른 상품에 섞이지 않게 한다. 저장·취소, 새로 열기, 이름 변경, 이동·되돌리기에서도 정보가 유지된다.

## 검수 및 배포 조건

- 이동 전후 ID/주문명/금액/사진 URL/옵션별 재고 비교.
- 중복 이름·가격·동시 수정·재시도·중간 실패·되돌리기 검사.
- 방송에 담긴 원본 및 과거 주문이 있는 원본의 조회·주문·챙김·집계 연계 검사.
- 세부상품별 정보와 상속/표시 안 함, 저장/취소, 사진 확대·모바일 가독성 검사.
- 운영 고객 상품을 임의로 이동하지 않는다. 격리된 검수 자료로 저장/복원 확인 후 사용자가 선택한 상품에서만 이동한다.
- 자동 검사, 빌드, 코드 리뷰, 운영 읽기 검수 후 배포 완료를 보고한다.
