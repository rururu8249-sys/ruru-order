# 판매분석 통합 설계

## 목적과 범위

관리자가 판매기록과 방송 리포트를 오가지 않고 기간별 판매 요약, 방송별 성과, 상품·옵션별 내역을 확인한다. 기존 주문·입금·정산 원본과 가격 계산은 변경하지 않는다. 상품 등록, 유튜브 실제 방송 시간 분석, 과거 은행 대조는 별도 작업이다.

## 확인한 현재 구조

- `AdminLiveProductManagePopup.loadHistory`는 결제완료 주문행 전체를 페이지별 조회하고 방송별 합계 및 품목 수를 만든다.
- `BroadcastReportPopup`는 선택 방송 주문행을 조회한 뒤 기존 주문 그룹 어댑터를 사용한다. 주문건수와 상품·옵션별 순위를 별도로 계산한다.
- 리포트에는 조회 실패 시 부분 결과 차단과 이전 방송 응답 무효화가 이미 구현되어 있다. 판매기록과 조회·집계 구현이 중복된다.
- 화면의 동일 금액만으로 모든 집계가 같다고 판단하지 않는다. 그룹 주문 수, 주문행 수, 판매수량을 별도 지표로 검증한다.

## 화면과 진입점

주 화면은 `주문·입금 → 판매분석`이다. 기존 `sales` 주소를 유지한다. 방송 메뉴의 리포트 진입점과 기존 `reports` 주소는 같은 판매분석 화면을 선택 방송과 함께 열며 별도 리포트를 다시 조회하지 않는다.

상단 순서는 기간·방송 검색, 요약 지표, 방송 목록과 선택 방송 상세다. 상세에는 요약, 상품·옵션별 내역, 베스트 상품, 구매자 분석을 둔다. 기존 상품 사진·옵션별 수량과 복사 기능은 보존한다. 좁은 화면에서는 목록과 상세를 세로 배치한다. 조회 상태, 기준, 새로고침을 화면에 명확히 표시한다.

## 데이터와 집계 계약

하나의 읽기 전용 조회 계층과 순수 집계 함수를 사용한다. 전체 합계와 선택 방송 상세는 같은 완료된 주문행 스냅샷에서 파생한다. 기존 주문 그룹 어댑터를 재사용하여 그룹 키를 임의로 만들지 않는다.

- 결제금액: 기존 결제금액 필드 우선순위와 주문 그룹 어댑터를 보존한다. 그룹별 결제금액과 주문행 금액의 기존 관계를 테스트로 입증한 후 공통화하며 배송비를 새로 더하지 않는다.
- 상품금액: 기존 조정 상품가격과 수량을 적용한 상품 합계. 결제금액과 구분해 표시한다.
- 주문건수: 기존 어댑터가 만든 결제완료 주문 그룹 수.
- 주문 품목 수: 포함된 주문행 수. 주문건수로 표시하지 않는다.
- 판매수량: 포함 품목의 수량 합계.
- 취소·삭제·영구삭제·테스트·정산제외·이벤트 선물은 기존 제외 규칙을 각각 대조하고 공통 필터 테스트로 고정한다. 차이는 숨기지 않고 구현 전에 원인과 영향 확인을 기록한다.
- 쇼핑몰 주문은 기존 `broadcast_id = null` 범위로 유지하며 방송 주문과 구분한다.
- 기간 필터는 방송에는 기존 방송 시작일, 쇼핑몰에는 기존 주문 생성일을 사용한다. 방송별 합계를 기간으로 임의로 쪼개지 않는다. UI에 이 기준을 표시한다.
- 구매자·객단가는 기존 리포트 그룹 기준을 유지한다. 확실한 원가·방송 시간 데이터가 없으므로 이익률·시간당 매출은 추가하지 않는다.

## 최적화와 오류 안전성

필요 필드만 선택하고 페이지 조회를 완결한다. 화면별 중복 조회와 중복 집계를 제거한다. 상세 선택에는 이미 검증된 주문행을 사용하며 사진·분류 보충 조회는 필요한 상품 ID로 제한한다. 공용 서버 가격 캐시, 고객 정보 브라우저 영구 저장, 서비스 권한 노출은 도입하지 않는다.

페이지 또는 보충 조회가 실패하면 성공한 일부 자료를 전체 합계로 표시하지 않는다. 오류와 재시도를 제공하고 0건과 실패를 구분한다. 요청 세대 또는 취소 처리를 통해 오래된 응답이 새 필터 상태를 덮지 못하게 한다. 새로고침 중 기존 자료를 유지한다면 이전 조회 자료임을 표시하고 새 필터의 자료로 오인시키지 않는다.

## 검증과 배포 조건

회귀 테스트는 다품목 한 주문, 동일 이름의 다른 가격, 옵션 내 슬래시, 조정가격, 배송비, 각 결제상태, 취소·선물·삭제·테스트, 쇼핑몰, 1000행 초과 페이지, 중간 조회 실패, 빠른 방송 전환을 포함한다. 실제 개인정보를 테스트 파일에 저장하지 않는다.

기존 판매기록·리포트 테스트 및 전체 테스트와 빌드를 통과해야 한다. 운영 검수는 읽기 전용으로 기존/통합 지표를 대조하고, 데스크톱·모바일에서 필터·사진·옵션·복사·오류 상태를 확인한다. 주문 생성이나 결제상태 변경으로 검수하지 않는다. 배포 전 실패하면 기존 운영 화면을 유지한다. 배포 후 문제 발생 시 이전 배포로 복구 가능한 상태를 유지한다.
