# 이벤트 방송 위젯과 관리자 화면 동기화

상태: 설계 검토용. 구현 완료 문서가 아닙니다.

## 목적과 범위

관리자가 사이트의 이벤트 시작 버튼을 눌렀을 때, 사이트의 이벤트 작업 화면에서도 OBS에 사용하는 같은 위젯의 실제 연출을 볼 수 있게 합니다. 당첨 안내는 작업 버튼을 가리지 않습니다. 기존 서바이벌·달리기·룰렛·인형뽑기·미션을 대상으로 합니다.

이 문서의 ‘사이트’는 요청에 첨부된 **관리자 이벤트 작업 화면**을 뜻합니다. 고객 주문 페이지에 새 이벤트 화면을 공개하거나 고객 개인정보를 추가 노출하는 변경은 포함하지 않습니다.

당첨자 결정, 당첨 확률, 참가자 기준, 포인트 금액 및 지급 정책은 바꾸지 않습니다. 운영 데이터에서 실제 추첨/포인트 지급을 실행하여 검수하지 않습니다.

## 현재 코드에서 확인한 원인

- 관리자 이벤트 패널은 OBS 위젯과 다른 자체 표시/애니메이션을 사용합니다. 서바이벌과 달리기는 시작 전 간단한 아이콘을 보여 줍니다.
- 서바이벌/달리기 위젯에는 브라우저별 Math.random 연출과 로컬 타이머가 있습니다. 같은 당첨자여도 중간 장면과 시작 시점은 일치하지 않을 수 있습니다.
- 위젯은 2.5초 간격 조회를 사용하며 첫 조회에서 이미 있는 결과를 건너뜁니다. 진행 중 새로 접속한 화면을 현재 장면으로 복구하지 못하는 구조입니다.
- 재생 판별에 result_at/updated_at을 사용합니다. 표현과 무관한 정보 갱신이 재생 판별에 영향을 줄 수 있습니다.
- 서버에 이미 spin_started_at, spin_duration_ms, result_at이 있습니다. 신규 기능을 위해 즉시 새 DB 필드가 필요하다고 단정하지 않습니다.
- 관리자 룰렛 완료 효과에 자동 포인트 지급 호출이 연결되어 있습니다. 표시 화면을 교체할 때 이 효과를 단순 삭제/복제하면 지급 누락·중복 위험이 있습니다.

근거 파일: components/admin-live/AdminLiveEventRoulettePanel.tsx, app/event-survival/live/page.tsx, app/event-race/live/page.tsx, components/event-roulette/EventRouletteOverlayClient.tsx, components/event-claw/EventClawOverlayClient.tsx, app/api/admin-live/event-roulette/route.ts, app/api/event-*/overlay/route.ts.

## 방식 비교와 추천

1. 관리자에 기존 위젯 iframe만 넣기: 화면 구성은 같지만 로컬 난수·타이머·조회 지연 때문에 연출 동기화는 해결되지 않습니다.
2. OBS 영상 자체를 관리자에 보여 주기: 송출 영상 지연 및 외부 방송 의존성이 생기며 이벤트만 독립적으로 검수하기 어렵습니다.
3. **추천: 같은 위젯 + 같은 이벤트 시간표**. 서버가 확정한 판과 시작 시간, 결정된 연출 정보를 모든 표시 화면이 공유합니다. 관리자는 OBS와 같은 위젯을 읽기 전용으로 표시합니다.

## 화면 설계

- 이벤트 선택 및 시작/테스트/재시작 버튼은 위젯 바깥에 둡니다.
- 기존 왼쪽 이벤트 영역을 실제 위젯 미리보기로 사용합니다. 같은 내용을 중복해서 그리는 별도 관리자 캔버스는 제거합니다.
- 관리자 미리보기는 기본 무음입니다. OBS의 기존 음향 설정은 유지합니다. 미리보기 중복 효과음이 발생하지 않게 합니다.
- 결과 요약은 시작 버튼 아래의 일반 행으로 표시합니다. 긴 닉네임과 안내문도 줄바꿈하고 버튼 위에 겹치지 않습니다.
- 로딩/통신 실패는 ‘연결 확인 중’ 또는 ‘다시 연결’로 표현합니다. 실패한 화면에 과거 당첨자를 새 당첨자처럼 보여 주지 않습니다.
- 기존 OBS 주소는 유지하고, 관리자는 현재 사이트 origin으로 같은 위젯 경로를 사용합니다. 하드코딩된 운영 도메인 때문에 로컬/미리보기 검수가 운영 이벤트에 연결되지 않도록 합니다.

## 동기화 데이터와 연출

- 읽기 전용 응답에 불변 이벤트 ID, 상태, 시작 시간, 시간표 버전, 서버 현재 시간을 제공합니다. 참가자 정보는 기존 공개 범위인 닉네임만 사용합니다.
- 이벤트 종류·ID·시작 시간·시간표 버전에 의해 연출 시드를 고정합니다. 참가자 배열 순서도 동일하게 고정합니다. 당첨 결과는 서버 확정값만 사용하며 클라이언트 난수로 다시 결정하지 않습니다.
- 화면 장면은 ‘현재 서버 기준 시간 − 시작 시간’에서 계산합니다. 브라우저가 읽은 시점이나 프레임 수가 연출 결과를 바꾸지 않도록 합니다.
- 서바이벌의 탈락 순서/재난, 달리기의 움직임/효과, 룰렛의 각도, 인형뽑기의 위치를 같은 시간에 같은 값으로 계산합니다. 장식 난수도 반복 생성하지 않습니다.
- 미션은 이미 공유하는 진행 상태를 같은 위젯으로 표시합니다. 불필요한 무작위 애니메이션을 새로 추가하지 않습니다.
- 기존 spin_duration_ms가 모든 종류의 실제 연출 길이를 표현하는지 검사하고, 종류별 시간표와 일치하도록 정리합니다. DB 마이그레이션 없이 해결할 수 있는지 구현 계획 단계에서 확정합니다.
- 이벤트 ID와 시작 시간으로 중복 연출을 판별합니다. updated_at이나 당첨 안내문 변경만으로 재시작하지 않습니다.
- 늦게 연 화면은 진행 중인 현재 장면으로 이동합니다. 이미 종료된 판은 완료 결과를 보여 주고 처음부터 다시 재생하지 않습니다.

## 통신·장애 처리

- 진행 중에는 짧은 조회 간격과 서버 시간 보정으로 수렴시키고, 대기 상태는 조회 빈도를 낮춥니다. 숨겨진 탭에서 돌아오면 즉시 상태를 다시 읽습니다.
- 네트워크 지연 때문에 모든 기기에서 0ms 차이를 보장하지 않습니다. 정상 연결 검수 목표는 두 화면의 시간차 500ms 이하이며, 실제 결과를 측정해 기록합니다.
- 500ms를 넘는 조회 지연은 숨기지 않고 ‘동기화 확인 중’으로 표시합니다. 네트워크 회복 시 새 추첨 없이 현재 시점으로 복구합니다.
- 시간표 버전이나 필수 시각이 없는 이전 이벤트는 완료 결과만 안전하게 표시합니다. 임의 시작 시간을 추정하지 않습니다.
- OBS 읽기 전용 화면/관리자 미리보기는 추첨·지급 API를 호출할 수 없습니다.

## 금전 처리 안전 경계

표시 애니메이션과 포인트 지급의 책임을 분리합니다. 현재 지급 호출의 조건과 이벤트별 중복 방지 키를 먼저 추적하고 테스트로 보존합니다. 위젯 새로고침, 관리자 재접속, iframe 두 개 실행, 통신 재시도에 의해 지급이 다시 발생해서는 안 됩니다.

공통 표시로 바꿨을 때 기존 지급 시점과 지급 횟수가 보존되어야 합니다. 기존 코드에 명확한 지급 중복 방지 근거가 없는 경우 해당 부분을 별도 결함으로 기록하고 안전한 보완 없이는 운영 배포하지 않습니다. DB/지급 의미 변경이 필요하면 변경 범위와 되돌리기 절차를 구현 계획에 명시합니다.

## 검수 및 배포 기준

1. 동일 이벤트와 동일 시각을 입력하면 두 렌더러의 위치/탈락/당첨 표시가 일치하는 순수 함수 테스트.
2. 브라우저 프레임 속도가 달라도 결과가 같은 테스트.
3. 늦은 접속, 새로고침, 재연결, 탭 숨김/복귀, 서버/기기 시간 차이 테스트.
4. 안내문 수정·일반 updated_at 변경이 재추첨/재연출/재지급을 유발하지 않는 테스트.
5. 다섯 종류의 운영 시작/테스트 시작 UI 흐름을 로컬 고정 응답으로 검수. 운영 지급은 실행하지 않음.
6. 관리자와 위젯을 별도 브라우저 화면에서 동시에 실행해 같은 시각의 장면과 결과를 비교. 정상 연결 지연 목표 및 복구 여부 기록.
7. 결과가 버튼을 가리지 않는 데스크톱/좁은 화면 검수. 긴 닉네임 및 다수 당첨자 포함.
8. 기존 전체 회귀 테스트, 타입 검사, UI 검사 및 빌드 통과. 추첨/지급 조건 변경 여부를 독립 검토.
9. 기능 단위 커밋으로 기존 Git 배포 사용. 실패 시 해당 기능 커밋을 되돌릴 수 있게 기존 OBS URL과 DB 호환성 유지.

## 설계 자체 검토

완료: 목적·대상 화면·다섯 종류·금전 경계·네트워크 한계·검수 조건을 명시했습니다. 동기화가 이미 구현된 것처럼 표현하지 않습니다. 이 설계 승인 후 파일별 구현 순서와 실행 계획을 작성합니다.
