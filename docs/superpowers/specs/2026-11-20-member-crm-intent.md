# 회원 관리 보완 — 기존 설계 확인 기록

기준: main `c1e5b5ff216a284c92b45cb0dfeb7e5ad64e1d3f` (PR #48).

## 사용자 요청

회원 목록·필터·로그인 정렬·상세를 운영하기 편하고 보기 좋게 보완한다. 모든 작업은 기존 설계 의도 확인 → 재현 → 수정 → 검증 순서로 진행한다. 중간 질문에 답해도 원래 작업을 계속한다. 추정으로 회원·주문 연결 기준을 바꾸지 않는다.

## 확인된 설계와 유지할 계약

- `CLAUDE.md` 고객 식별 원칙: 고객의 정본은 카카오 계정 및 customers.id. 전화번호는 변경 가능한 연락처 및 과거 자료의 보완 경로다.
- 로그인 커밋 `4d532909623b15a0b014e560a431d20e060c4960` 및 `customer-login-sync`의 `canonicalKakaoId`: 같은 번호로 다른 카카오 계정을 쓰는 실제 사례를 기존 회원으로 연결하도록 수정했다. 여러 카카오ID라는 사실은 다른 사람이라는 증거가 아니다.
- `lib/customerIdentity.ts`: 관리자 표시 묶기는 기존 연결을 쪼개지 않는다. `selectBackfillPhoneDigits`의 쓰기 보호와 표시 묶기를 혼동하지 않는다.
- `lib/customerOrderLookup.ts`, `CustomerFullOrderHistory.tsx`: 내 카카오 주문과 카카오ID가 NULL/빈 문자열인 같은 번호의 과거 주문을 조회한다. 이미 다른 카카오ID가 명시된 주문은 별도다. 현재 회원 소유가 충돌하는 경우의 집계 보류 규칙도 이번 작업에서 바꾸지 않는다.
- `test-customer-identity`, `test-customer-order-lookup`, `test-member-lifetime-20261119`의 기존 기대값을 유지한다. 과거 주문을 제거하도록 기대값을 바꾸던 미배포 v4 안은 폐기한다.
- `CLAUDE.md` 2026-09-05/09-25 회원 규칙: 최근 주문순 기본, 주문 있는 고객만 기본 OFF, 검색·상태·8개 정렬·초기화 유지. 과거접속순은 접속기록 없는 회원 먼저. 목록 20명 추가정보 일괄조회는 부하를 고려한 기존 설계이므로 임의로 변경하지 않는다.
- `DESIGN-ADMIN.md`는 기존 로즈 시안보다 최신인 관리자 디자인 기준이다. 흰 판·회색 바탕·검정 주버튼, 720px 오른쪽 상세, 폰 전체화면, 44px 터치, 16px 폰 입력, 숫자 우측 정렬·tabular-nums, 짧은 문구를 적용한다.
- 회원 수정·차단·포인트·번호 변경·계정 잇기·로그인 API와 실제 금전·주문 데이터는 이번 UI 보완에서 재설계하지 않는다.

## 확인한 문제와 범위

1. 상세 이력 실패를 빈 배열로 바꿔 부모에 0건/0원 전달: 실패·로딩과 실제 빈 이력을 구분하고 재조회 제공.
2. 가입·로그인 날짜가 둘 다 없을 때 comparator가 양 방향에 같은 부호를 반환: 두 값 부재를 동률 처리, 기존 결측값 위치 유지.
3. 차단목록 상세 진입이 `openDetail`을 우회: 같은 회원 선택 경로 재사용.
4. 회원 전체 행 수와 표시 가능한 프로필 수를 비교하여 준비 완료가 되지 않을 수 있음: 읽은 전체 행 수로 검증하고 조회 예외/페이지 상한을 명시적으로 처리.
5. 전 기간 상태 분류의 `paid` 부분 문자열이 `unpaid`에 일치하고 `출고`가 `출고대기`에 일치: 기존 상태 사전·isPaid의 미결제 우선 계약으로 재현 후 표시 집계만 수정. 출고완료 과거 자료의 기존 호환 테스트는 유지.
6. 포인트 상세에서 P가 아닌 원을 표시하고 과거 미구현 안내가 남음: 숫자·요청 payload는 그대로 두고 단위·문구·배치 정리.
7. 중앙 상세창, 작은 글자/터치 영역, 중복된 정보, 로딩·오류·재조회 일관성: 확정 디자인에 맞춰 표시 개선.

## 접근 방식

전체 식별 체계 교체나 프로필만으로 목록을 새로 만드는 안은 기존 호환 목적과 충돌하여 채택하지 않는다. CSS만 덧붙이는 안은 조회 실패·정렬·선택 결함을 고치지 못한다. 기존 경로를 보존하며 재현된 결함과 화면 구조를 단계별로 수정한다.

접속 기록 정책은 이미 적용된 visitor_visits service_role 전용 정책과 실제 읽기/쓰기 사용처를 별도로 대조한다. 모든 직접 사용처는 서버이며 공개 시청자 수는 visitor_presence를 사용한다. 서비스 키 미설정 시 anon으로 떨어지는 두 서버 경로는 별도의 조건부 위험이며 운영 키 누락으로 단정하지 않는다. 이 기록은 다른 테이블 권한 변경의 승인이 아니다.

## 완료 판정

기존 식별 테스트 변경 없음, 추가 재현 테스트, 관리자 UI/결제 안전 가드, TypeScript, 전체 production build, 독립 코드 리뷰, PC·360/375/390/430 화면 검사. 배포와 실제 운영자 실화면 확인은 별도 상태로 기록한다. 부분 통과를 전체 무결함으로 표현하지 않는다.

## 구현 및 검증 기록 (2026-11-20)

- 회원 상세는 회원 키별로 상태를 다시 만들고, 이전 회원 저장 응답이 새 회원의 상세를 닫거나 값을 덮지 않도록 처리했다. 구매자 필터가 켜진 채 새로고침해도 조회가 끝나기 전 비구매자가 나타나거나 일괄 선택되지 않는다.
- 전 기간 조회 실패는 `null`/오류 상태로 유지한다. 성공한 실제 0건만 0으로 표시한다. 프로필 전체 행 수로 완료 여부를 확인하고 같은 날짜 행의 페이지 순서에 id를 더했다.
- 기존 정렬 8개, 최근 주문순 기본, 주문 없는 회원 포함, 과거접속순에서 기록 없는 회원 먼저라는 계약을 유지했다. 차단 상세에서도 일반 상세와 같은 프로필·배송지를 불러온다.
- 제공된 6개 화면에서 확인한 중앙 상세창·중복 누적금액·작은 터치 영역·포인트 원 단위를 확정 디자인에 맞춰 보완했다. 오른쪽 720px 상세/폰 전체, 고정 머리·닫기, 4개 탭, P 단위, 조회 재시도, 모바일 연락처 및 긴 문자열 줄바꿈을 적용했다. 새 버튼은 밝은/어두운 테마의 ink/surface 토큰을 함께 사용한다.
- `AdminLiveCustomerBlockReasonModal`에 기존 공용 모달 포커스 관리를 적용했다. 실제 차단·포인트 지급·전화번호 변경 요청 payload와 서버 API는 변경하지 않았다.
- 관리자 UI 가드는 기준 커밋부터 26건이 있었다. 기존 DESIGN-ADMIN.md 위반 스타일을 보정했고, 조건부 선택색/짧은 다음 행동의 오탐을 수정했다. 테스트에서 실제 잘못된 hover 6종, 잘못된 글자 크기, 다음 행동 없는 빈 안내는 계속 거부한다. 최종 121파일·0건.
- 옵션 가드의 기존 4건 중 3건은 옵션이 아닌 문장·상품 검색 토큰화였다. 확인한 수신자 포함 정확한 표현식에만 예외를 적용했다. 실제 안내문 생성의 `XS/S → XS`는 `lib/optionSplit.ts`의 2026-09-08 사용자 규칙 위반이었다. 서버의 등록 sizes 배열(빈 배열 포함)을 우선 사용하고 레거시 명시 필드만 보완 조회한다. `/`, `|`, `·`, 공백이 든 옵션 이름 및 배열 경계, 색상명 `블랙/사이즈업`을 실제 생성 함수로 검증했다. 가격 판정·상품/주문 DB 쓰기는 변경하지 않았다.
- 기존 identity/order-lookup/lifetime 기대값은 그대로다. 모바일 테스트는 레이아웃의 정확한 Tailwind 문자열 의존만 안정적인 `data-member-cards` 선택자로 바꿨고 동작 검증은 유지했다.

### 검증 범위와 남은 확인

- 로그인 테스트가 실제 카카오 OAuth부터 정본 ID 보정까지 전체 운영 경로를 검증한 것은 아니다. 보정 코드와 기존 연결 기대값은 변경하지 않았다.
- 번호 변경 테스트는 판단 함수·UI의 늦은 응답 경계를 확인했다. 운영 DB 트리거를 실제 번호 변경으로 실행하지 않았다.
- PR #49가 main `43297a024fc302bb2cee0330f27f4d77325f6ac1`에 병합되고 Vercel success인 것을 확인했다. 운영 브라우저 PC/360/375/390/430px에서 가로 넘침, 상세 폭/높이, 8종 정렬·검색·구매자 필터, 상세 4탭, 사진/포인트 중첩 창 Esc·포커스 복귀를 읽기 전용으로 확인했다. 새로 발견한 닫기 중복·차단 위치·주문 경계·필터 시각 구조는 후속 UI 수정 대상이다. 터치 실기기·한글 입력기·다크모드 전체 실화면까지 검증한 것은 아니다.
- visitor_visits 정책·직접 호출처를 읽기 전용으로 확인했으며 DB 정책 변경은 없다. 배포 후 실제 접속 기록과 방문 통계 조회가 성공하는 것을 확인했다. heartbeat 쓰기·정리 삭제는 실행하지 않았고, Vercel 환경변수 내용도 읽지 않았으므로 해당 전체 경로 검증으로 확대하지 않는다.
- 작업 원칙을 `AGENTS.md`에 기록했다. ChatGPT 장기 메모리 쓰기 기능이 제공되지 않아 장기 메모리 저장 완료로 표시하지 않는다.
