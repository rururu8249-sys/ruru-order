# CRM 운영 구조 단순화 — 실행 기준

## 최상위 작업 지침 — 사용자 재확인

목표는 기능 추가나 일부 화면 미화가 아니라 급하게 덧붙인 사이트 전체를 운영하기 편한 구조로 재정리하는 것이다. 책의 문장이 아니라 목차와 장의 구성부터 바로잡는다.

순서는 반드시 **현재 구조 파악 → 운영 흐름 정리 → 전체 목차 재설계 → 화면 설계·구현 → 실제 흐름 검증**이다. 전체 CRM 관리자와 고객 주문서가 중심이며 모바일은 후속 대응이다. 참고 영상·사이트는 복제가 아니라 운영 원칙을 우리 흐름에 맞게 적용하기 위한 자료다.

추가 요청은 진행 중인 작업을 끊는 새 최우선 과제가 아니다. 현재 작업을 마무리하고 전체 설계 아래 순서대로 편입한다. 조사하지 않은 사항을 확인했다고 하지 않고, 일부 수정이나 테스트 통과를 전체 완료로 표현하지 않는다.

2026-10-10 상태: 반품 포인트 복원 안전성 변경은 82c2987 운영 배포 확인. 공지 연결은 로컬 구현·테스트 상태이며 아직 운영 반영 전. 이 변경을 마감한 뒤 게시판 등 추가 화면 작업으로 곧바로 넘어가지 않고 전체 구조·업무 지도와 메뉴 설계를 먼저 완성한다. 위 설계 우선순위가 아래 개별 작업 목록보다 우선한다.

## 목적과 범위

운영자가 추가 요청을 반복하며 생긴 기능 중복과 이동 비용을 줄인다. 모바일만 고치거나 기능을 더 늘리는 작업이 아니다. 고객 주문 → 입금 확인 → 상품 챙기기 → 고객 응대·취소·환불 → 판매 확인의 전체 업무를 기준으로 관리자와 고객 화면을 함께 정리한다.

사용자는 일상적인 승인 질문으로 멈추지 말고 순서대로 실행한 뒤 함께 검토하라고 명시했다. 따라서 설계 판단은 근거와 함께 기록하고 진행하되, 실제 고객 금전·발송·주문 상태를 시험 삼아 변경하지 않는다.

## 참고 자료의 적용과 제외

- Qshop 공식 운영관리 가이드(2026-10-10 재확인): 운영 업무와 상점 설정을 구분하는 원칙만 적용한다. 메뉴·기능 전체를 복제하지 않는다. https://help.qshop.ai/customer_support/guide/admin
- 구매확정 기능은 추가하지 않는다. 우리 판매 집계는 현재 결제완료 기준을 유지한다. 집계 변경은 UI 정리와 분리하여 검증한다.
- Doweb 메뉴 구조 글은 이번 도구 조회 실패. 기존 조사 산출물과 구분하며 이번에 본 것처럼 주장하지 않는다.
- 유튜브 전체 연속 시청 완료라고 주장하지 않는다. 기존 영상 조사 기록의 자막/표본 화면 확인 범위를 유지한다.

## 설계 선택

1. 메뉴명만 수정: 비용은 적지만 중복 데이터와 업무 흐름 문제는 남음 — 채택하지 않음.
2. 전면 교체: 기존 데이터·업무 습관·결제 경로의 위험이 큼 — 채택하지 않음.
3. 기존 데이터와 기능을 보존하며 업무 단위로 통합: 채택. 메뉴 구조, 작업 화면, 상태 검증을 단계별로 바꾸고 회귀 테스트한다.

## 목표 구조와 책임

- 방송: 방송 준비·진행과 채팅주문. 기존 화면·이벤트 연동을 보존.
- 주문·입금: 주문 처리와 입금 확인, 물건 챙기기, 판매 확인 및 정산. 합계 기준은 명시하고 회계 계산은 화면 개편과 별도로 유지.
- 상품: 등록·수정·옵션 판매상태. 안내 문구와 재고 수량, 판매 가능 여부를 서로 다른 개념으로 표현.
- 고객: 고객 찾기와 미해결 이슈. 공지·쪽지는 공개 게시/개인 발송으로 구분하되 입력 UI와 기록을 중복 만들지 않음.
- 설정: 상점 기본값과 연동만. 실제 게시·발송 등 일상 작업은 설정에 복제하지 않고 해당 작업으로 연결.

불필요 기능의 판단 기준은 중복 진입점, 동일 데이터의 중복 편집, 작동하지 않는 연결이다. 사용량이 낮다는 증거 없이 기능이나 데이터 삭제 금지. 중복 UI를 먼저 제거하고 원본 기록은 보존한다.

## 공지·쪽지 상세 설계

공지는 한 번 작성하고 노출 위치를 정한다. `notices`가 제목·본문의 원본이며 상단/접속 팝업은 선택한 공개 공지를 참조한다. 개인 쪽지는 기존 대상자/발송/읽음 기록을 사용한다.

기존 popup 내용은 자동 삭제·덮어쓰기하지 않는다. 선택된 공지가 없는 기존 상점은 기존 공지를 그대로 표시한다. 공개 공지를 선택해 저장한 뒤에만 새 연결을 사용한다. 비공개·삭제된 공지는 원문을 노출하지 않으며 오래된 다른 공지로 조용히 바꾸지 않는다.

상단 고정 공지의 문구는 선택한 공지의 제목 그 자체다(사용자 재확인). 별도 요약 문구나 기존 popup_notice_bar가 연결된 공지 제목을 덮어쓰면 안 된다. ‘자세히’를 누르면 같은 공지의 본문이 바로 열린다. 일반 공지함 진입은 목록을 연다. 개인 쪽지 읽음 처리와 공개 공지 열기는 구분한다. 로딩 실패를 빈 공지로 오인하거나 기존 주문 입력을 초기화하지 않는다.

관리자는 기본 화면에서 공지 목록/작성, 쪽지 보내기/발송 기록만 이해하면 된다. 색상·글꼴·부가 안내는 필요할 때 펼친다. 자동 발송은 실행하지 않는다.

### 고객 공지 목록 — 추가 참고 화면(2026-10-10)

사용자가 제공한 천사의 손 화면에서 참고할 것은 번호·등록일·제목의 게시판형 목록, 목록 하단 제목+내용 검색, 하단 페이지 이동이다. 큰 공지사항 히어로 이미지·제목은 복제하지 않는다. 제목 클릭은 해당 본문으로 연결하고 상단 고정 공지의 직접 본문 열기와 혼동하지 않는다. 이 목록 작업은 현재 상단 공지 연결 단위를 검증 완료한 다음 수행한다. 개인 쪽지 내용이 공개 검색에 포함되지 않도록 데이터 경계를 유지한다.

추가 본문 참고 화면: 제목 클릭 → 본문 → 본문 아래 ‘이전글·다음글·목록’. 목록 복귀 시 검색어와 페이지를 유지한다. 이전/다음은 현재 공개 목록의 정렬 순서를 따르고 대상이 없으면 이동하지 않는다. 큰 장식 헤더나 화면을 덮는 연락 버튼은 복제하지 않는다.

## 순차 실행과 검증

1. 현재 반품 포인트 복원 변경을 테스트·배포 확인까지 마감. 기존 첫 회수와 이슈 삭제 경쟁 조건은 별도 잔여 위험으로 기록하며 완전 해결 주장 금지.
2. 전체 메뉴와 설정의 입력·저장·사용처를 조사하여 위 표를 확장. 이전 설계와 사용자 지정 위치를 확인.
3. 공지 작성→노출→상세 연결을 먼저 한 흐름으로 완성. 기존 공지 호환, 삭제/비공개, 오류, 개인 쪽지 보호 테스트.
4. 설정의 기본/고급과 중복 진입 정리. 숨김으로 접근 불가능해지는 기능이 없는지 테스트.
5. 상품등록 추가 요청: 조용한 문구 잘림 제거, 재고 OFF에서도 옵션별 판매차단. 고객 화면·장바구니·서버 접수에서 동일 규칙.
6. PC 전체 업무 회귀 확인 후 좁은 화면 확인. 완료/미완료/운영 데이터 확인 필요를 구분해 보고.

## 완료 기준

각 기능은 목록 등록만으로 완료가 아니다. 코드 변경, 자동 테스트, 빌드, 배포 SHA 확인, 비파괴 화면 확인을 각각 기록한다. 사이트 전체 완성은 위 모든 단계의 확인 이후에만 선언한다.
