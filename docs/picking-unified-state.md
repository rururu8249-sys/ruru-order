# 물건챙기기 — 단일 챙김 상태

## 운영 기준

- 방송 주문목록에서 물건챙기기를 열면 방송·날짜·주문 범위·검색에 해당하는 대상 ID를 고정한다. 창 밖 결제/작업 상태 필터는 넘기지 않는다. 창 안 결제완료 기본 / 미결제 포함 / 미결제만으로 조회한다. 미결제는 체크할 수 없다. 취소/챙기기 제외 주문은 표시하지 않는다.
- 상품별 / 고객별은 동일한 주문 상품 행을 다른 기준으로 묶어 보여준다. 상태는 `orders.picked_at` 하나다.
- [㉗ 2026-10-15] 상품별 화면 구조 = 상품 → 옵션별 합계 → 그 옵션을 산 손님.
  - 상품 머리(rose-soft): 그 상품 첫 사진 56px + 상품명 18px 굵게(h3), 오른쪽 「총 N개」 20px + 「챙김 n/N」 12px.
  - 옵션 머리(surface-2): 같은 optionText(없으면 「기본 옵션」)끼리, 순서는 행 정렬(compareOrderOptions) 첫 등장 순. 옵션명 16px rose-deep(h4), 오른쪽 「N개」 18px + 「n/N」 12px, 전부 챙기면 초록 「✓ 다 챙김」 배지. 옵션 사진은 상품 사진과 다를 때만 40px.
  - 손님 줄: 사진 없음. 「닉네임 · 이름 · 주문 #id」 14px, 수량(2개 이상 빨강), 기존 「챙김 완료」 버튼(44px). 챙긴 줄은 초록 배경(opacity 금지). 결제 후 추가·다시 챙기기·미결제 배지와 변경 전후 안내는 손님 줄 안.
  - 옵션·상품 단위 「한 번에 챙김」 버튼은 없다(한 줄씩 확인). 고객별 화면은 기존 그대로.
- 사진, 상품명, 색상/사이즈, 고객/주문 행 번호, 수량을 확인한 뒤 해당 행의 챙김 버튼을 누른다. 수량이 여러 개면 해당 수량 전부에 대한 체크다.
- [㉖ 2026-10-15] 「일반 챙김」 탭은 이전에 챙긴 행도 계속 보여준다(초록 배경 + ✓ 챙김 완료 버튼, opacity 흐림 금지). 창을 닫았다 열어도 같다. 탭 숫자는 남은 수량, 「현재 목록 모두 챙김 완료」는 안 챙긴 행만 대상. 「결제 후 추가 챙기기」·「상품 변경 · 다시 챙기기」 탭은 기존대로 이번에 체크한 행만 남긴다. 「챙김 완료」 탭은 챙긴 행만.
- 행 전체 클릭이나 전체 완료 버튼은 없다. 완료한 행은 자동으로 접거나 이동하지 않는다. 안 챙김만 필터는 선택적으로 사용한다.
- 주문목록의 작업 표시와 피킹 엑셀도 같은 챙김 기준이다. 모달 닫기 후 주문목록을 다시 조회한다.
- 역사적인 `collected_at`(모음)은 삭제/변환하지 않는다. 모음만 기록된 건을 완료라고 추정하지 않는다.
- 전체보기 / 안 챙김만 / 챙김만과 각 수량을 명시한다. 수량은 선택 결제 범위 기준, 검색과 챙김 필터는 목록만 좁힌다.
- 상품별: 자연 숫자 상품번호순 / 남은 수량 많은순. 고객별: 닉네임순 / 주문 오래된순 / 남은 수량 많은순. 남은 수량 정렬은 선택 시점의 완료 상태로 유지하고 '다시 정렬'로 갱신한다. 안 챙김 필터로 일부 행이 빠져도 남은 그룹 순서는 바뀌지 않는다.
- [㉖ 2026-10-15] '물건챙기기 엑셀'은 서버에서 다시 조회한 적용 범위(선택 방송+오늘 추가 작업)의 **결제완료 행 전부**를 챙김 여부와 관계없이 내보낸다. 활성 탭·검색은 엑셀에 적용하지 않는다. 범위 이름은 「결제완료 전체」. 메인 시트 맨 끝 「챙김」 칸에 챙긴 행은 ✓, 아니면 빈칸(다시 챙기기 대기 행은 빈칸). 출력 기록(picking_list_printed_at)은 내보낸 행에만 처음 시각으로 남긴다. 결제완료 행도 고객이슈도 없으면 「내보낼 결제완료 상품이나 미처리 고객이슈가 없습니다」. '더보기 > 조회 목록 챙김 해제'는 보이는 결제완료 항목만 확인 후 해제한다.

## 저장 안전장치

- 주문/입금/재고/출고/금액은 변경하지 않는다. 체크 저장은 `picked_at`만 갱신한다.
- 서버가 대상 행 전부의 저장 결과를 반환하고 확인한 뒤에만 완료 표시를 변경한다.
- 초기 조회/저장 중에는 체크를 막는다. 빠른 연속 클릭 및 중첩 저장을 막는다.
- 오래된 조회가 새 저장 결과를 덮어쓰지 않도록 조회 세대를 관리한다. 저장 중 실시간 갱신은 저장 종료 후 다시 조회한다.
- 저장 실패 시 실제 상태를 다시 조회한다. 재조회도 실패하면 경고하고 체크를 막는다.
- 주문목록 작업 필터가 바뀌는 실시간 완료 갱신 때문에 현재 작업 중인 주문이 사라지지 않도록, 열 때 대상 주문 ID를 유지하고 내용은 최신 데이터로 해석한다.

## 검수

`npm run test:picking`: 단일 상태 집계, 저장/해제, 권한으로 0행 반환, 잘못된 저장 결과, ID 검증, 500행 분할, 결제/취소/제외 범위, 옵션 문구 보존, 중복 클릭, 서버 확인 전 완료 금지, 두 화면 체크/해제 연동, 실패, 필터, 재열기, 구분자 없는 검색, 실시간 갱신과 저장 경쟁.

실제 고객 주문을 테스트 목적으로 챙김 처리하지 않는다. 바코드 실물 대조 및 여러 작업자 간 독점 잠금은 이 변경에 포함되지 않는다.
